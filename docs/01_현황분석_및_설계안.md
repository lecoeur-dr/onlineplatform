# 온라인 교무실 웹앱 — 현황 분석 및 설계안

## 0. 결론 요약

| 항목 | 결론 |
|---|---|
| 근본 문제 | **입력(데이터)과 보기(화면)가 한 시트에 섞여 있음** → 해마다 틀을 다시 짜야 하고, 한 셀에 여러 정보를 넣다 보니 수정할 때 어긋남 |
| 해결 원칙 | 데이터는 **"한 줄 = 한 건"** 표로만 저장하고, 달력·시간표·대시보드 화면은 **웹앱이 자동으로 그림** |
| 구현 방식 (확정) | **Cloudflare Workers 웹앱 + D1 데이터베이스 + 구글 계정 로그인(개인 Gmail)** — 구글 시트·앱스스크립트와 분리 |
| 범위 (확정) | **기존 17개 시트 전부 이관** — 규칙이 있는 시트는 메뉴로, 모양이 불규칙한 부분은 '자유 표'로 그대로 |
| 연도 기준 (확정) | 연도 = 1월~12월, 단 학사일정(3월~2월) 때문에 **학년도 Y 화면은 Y년 1월 ~ Y+1년 2월(14개월)** 을 함께 보여 줌 |
| 보안정보 (확정) | 비밀번호·연락처도 학교 공유용으로 올림 → **로그인+관리자 승인한 교직원만**, 비밀번호는 **암호화 저장 + '보기' 누를 때마다 기록** |

## 2. 불편의 원인 — 시트에서 직접 확인한 근거

### 2-1. 해마다 틀을 다시 짜야 함 (셋팅이 불편한 이유)
- 월별달력 셀마다 연도·월·열 위치가 **수식 안에 직접 적혀 있음**
  - 예: `=IFERROR(VLOOKUP(DATE(2026, 9, BX2), '월별교육활동'!$BE:$BG, 3, 0), "")`
  - 13개월 × 약 35칸 = 수백 개 수식이 `2026`, `9`, `$BE:$BG` 같은 값을 각각 들고 있음
- 날짜 숫자(1, 2, 3…)와 첫 주 시작 칸도 달마다 손으로 배치
- → 새 학년도가 되면 **거의 새로 만들어야 함**

### 2-2. 한 셀에 여러 건을 넣어서 수정이 어려움 (수정이 귀찮은 이유)
- 월별교육활동의 하루 = 한 행, 그 날의 행사 여러 개를 **줄바꿈으로 한 셀에** 입력
- 담당자·장소도 별도 셀에 줄바꿈으로 입력 → **줄 순서를 눈으로 맞춰야 함**
  - 예: 9월 2일 — 행사 4줄, 담당 `예술/교무/학맞통`, 장소 `체육관/AI실/체육관` → 어느 행사가 어느 담당인지 줄 수가 달라 어긋남
- 결과: "우리 부서 행사만 보기", "체육관 쓰는 날 보기" 같은 **필터가 불가능**

### 2-3. 같은 내용을 여러 곳에 중복 입력
- SW·AI 수업: `월별교육활동`(9/4 "SW·AI 수업(4,5학년)")과 `SW·AI수업 시간표`(9/4 달력 칸) **두 곳에 따로 입력**
- 일정 변경도 텍스트로 기록: `11 (10/16로 변경)` → 달력에는 자동 반영 안 됨
- 예술 시간표도 달력 모양을 손으로 다시 그림

### 2-4. 학급명이 날짜로 바뀌는 문제
- `1-1`, `5-2` 같은 학급명이 **날짜 값(2026-01-01, 2026-05-02)으로 저장**됨
  - 확인 위치: 시간표, 동료장학(수업교실·수업공개 반), 신발장, 공모사업(운영대상학년 `1-6` → 2026-01-06)
- 화면에는 서식 덕분에 정상처럼 보일 수 있으나 [확인 필요], **정렬·검색·집계 시 오류 원인**

### 2-5. 계산 방식 불일치
- 운영물품 `금액` 열: 일부 행은 수식(`=D*E`), 일부 행은 숫자 직접 입력
  - 예: 8번 행 단가 72,550 × 수량 1 인데 금액 89,000 입력 → **총금액 합계가 실제와 달라질 수 있음**
- 월별 `수업일수 : 일` 칸이 비어 있음 → 행사 데이터로 자동 계산 가능

### 2-6. 보안
- `비번및내선`: 쇼핑몰 계정·비밀번호, 출입문·와이파이 비밀번호
- `AI플랫폼(계정)`, `AI디지털`: 교사 개인 연락처
- 시트 공유 권한이 있는 사람은 **모두 열람 가능** → 웹앱에서는 관리자만 보이게 분리 권장

## 3. 설계 원칙

| 원칙 | 설명 | 효과 |
|---|---|---|
| ① 한 줄 = 한 건 | 행사 1개 = 1행 (날짜·제목·담당·장소 각각 칸) | 수정·삭제·필터 쉬움 |
| ② 입력은 폼, 보기는 자동 | 교사는 입력 폼만 사용, 달력·목록은 웹앱이 그림 | 틀이 깨지지 않음 |
| ③ 기준정보는 한 곳에서 | 교직원·학급·부서·장소를 목록으로 관리 → 전부 드롭다운 | 표기 통일(규격) |
| ④ 학년도는 설정값 1개 | `학년도=2026`만 바꾸면 달력·시간표가 새로 계산 | 연도 전환 5분 |
| ⑤ 권한 분리 | 관리자 / 부서담당 / 교사 / 열람 | 보안정보 보호, 실수 방지 |
| ⑥ 데이터는 시트에 그대로 | 웹앱이 구글 시트를 저장소로 사용 | 백업·엑셀 다운로드 기존처럼 가능 |

## 4. 구현 방식 비교

> **2026-09-30 결정:** 구글 시트를 개인·공유용으로 이미 많이 쓰고 있어 앱스스크립트는 쓰지 않고, **Cloudflare 배포 웹앱**으로 확정. 아래 표는 검토 기록으로 남김.

| 방식 | 장점 | 단점 | 적합도 |
|---|---|---|---|
| **A. 앱스스크립트 웹앱 + 구글 시트** (추천) | 무료, 구글 로그인 그대로, 데이터가 드라이브에 남음, 학교 이동 시 복사 쉬움 | 화면 로딩 1~3초 수준, 동시 저장 시 잠금 처리 필요 | ★★★ |
| B. 노션 데이터베이스 | 달력·보드 보기가 기본 제공, 제작 빠름, 교사 무료 요금제 있음 | 교직원 전원 노션 가입 필요, 수식·자동계산·권한 세분화 한계, 학교 데이터가 외부 서비스에 저장 | ★★ |
| C. 전용 웹앱 (Next.js + Supabase 등) | 속도·디자인·확장성 최고 | 호스팅·유지보수 부담, 담당자 교체 시 운영 중단 위험 | ★ (추후 여러 학교 배포 시 검토) |

> A안을 추천하는 이유: 지금 시트 데이터를 그대로 옮길 수 있고, 내년·타 학교에 **"시트 복사 + 설정 1개 변경"**으로 재사용 가능.

## 11. 실제 데이터 구조 (구현)

설계안 6장의 표 구조를 모두 하나의 `records` 테이블에 **메뉴(module)별 규격**으로 저장합니다. 규격은 `public/js/modules.js` 한 파일에 모여 있어, 칸을 추가하거나 드롭다운 목록을 바꿀 때 이 파일만 고치면 됩니다.

| 구분 | 메뉴 | 조회 방식 |
|---|---|---|
| 날짜 기록 | 학사일정, 출장, 특별수업, 월별 안내, 회의록 | 날짜로 조회 → 1~2월 기록은 두 학년도에 함께 보임 |
| 연도 기록 | 안내사항, 시간표, 동료장학, 물품 신청, 공모사업, 공모 안내, 예산, 자유 표 | 학년도별 → 다음 해로 복사 기능 |
| 공통 기록 | 바로가기, 위임전결, 내선번호, 계정·비밀번호 | 연도 구분 없음 |

## 13. 배포 버전 3종 (2026-09-30 결정)

> Cloudflare·앱스크립트 모두 사용량 한도가 있으므로, 학교 상황에 맞게 고를 수 있도록 3가지로 나눈다.

| 버전 | 대상 | 서버·저장 | 한도 | 로그인·권한 | 만드는 방식 |
|---|---|---|---|---|---|
| ① Cloudflare | 우리 학교 (내 계정) | Workers + D1 | Cloudflare 무료 한도 (1개 학교는 약 10% 예상) | 구글 로그인 + 관리자 승인 | **완성 (배포 전)** |
| ② 구글 앱스크립트 | 웹앱 화면을 원하는 다른 학교 | 학교별 앱스크립트 + 구글 시트 | 학교별 구글 계정 한도 (동시 실행 사용자당 30 등) | 일반 구글 계정, 비공개·권한자에게만 공유 | ①의 화면·규격 재사용, 서버만 교체 |
| ③ 스프레드시트 재구조화 | 스크립트 없이 쓰고 싶은 학교 | 구글 시트만 (수식) | 스크립트 한도 없음 (시트 용량 한도만) | 시트 공유 권한 그대로 | ①의 규격을 시트 구조로 옮김 |

### ③ 스프레드시트 재구조화 방향

지금 시트의 불편(해마다 다시 셋팅, 한 칸에 여러 행사, 중복 입력)을 **스크립트 없이 수식만으로** 해결하는 구조.

| 원칙 | 구현 |
|---|---|
| 입력 탭은 "한 줄 = 한 건" | `일정`, `특별수업`, `출장`, `회의`, `시간표`… 탭마다 ①과 같은 칸 구성 |
| 드롭다운 규격 | `설정` 탭의 부서·장소·학급 목록 → 데이터 확인(드롭다운) |
| 연도는 한 칸 | `설정!학년도` 한 칸만 바꾸면 달력 14개월(1월~다음해 2월)이 다시 계산 |
| 보기 탭은 자동 | `월별달력`·`대시보드`는 FILTER/QUERY 수식으로 입력 탭에서 끌어옴 (직접 입력 안 함) |
| 학급명 오류 방지 | 학급·교실 칸은 '일반 텍스트' 서식 고정 → `1-1`이 날짜로 바뀌지 않음 |
| 비밀번호 | 시트는 공유된 사람 모두가 볼 수 있으므로, **별도 파일로 분리**해 필요한 사람에게만 공유 [확인 필요: 학교별 운영 방식] |

- 한계: 동시 수정 충돌 안내, 승인·권한 단계, 변경 기록 화면은 없음 (구글 시트 자체의 '변경 기록'으로 대체)

### 진행 순서 (제안)

1. ① Cloudflare 배포 → 시범 사용 → 기능 확정
2. ③ 스프레드시트 재구조화 (①의 규격이 확정되면 탭 구조로 바로 옮길 수 있음)
3. ② 앱스크립트 (①의 화면 + ③의 시트 구조를 저장소로 사용하면 두 버전이 데이터 호환)
