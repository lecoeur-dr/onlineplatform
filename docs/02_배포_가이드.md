# 온라인 교무실 — Cloudflare 배포 가이드

> 처음 한 번만 하면 되는 작업입니다. 소요 시간은 약 30~40분으로 예상합니다.
> 명령어는 PC의 터미널(또는 Claude 앱)에서 이 저장소 폴더 안에서 실행합니다.

## 전체 흐름

| 순서 | 할 일 | 어디서 |
|---|---|---|
| 1 | 준비물 설치, 코드 받기 | 내 PC |
| 2 | Cloudflare 로그인, 데이터베이스 만들기 | 터미널 |
| 3 | 1차 배포 → 웹앱 주소 확인 | 터미널 |
| 4 | 구글 로그인 키 만들기 | Google Cloud 콘솔 |
| 5 | 비밀값 등록, 관리자 이메일 지정, 재배포 | 터미널 |
| 6 | 관리자 첫 로그인 → 엑셀 가져오기 | 웹앱 |
| 7 | 선생님들께 주소 안내 → 승인 | 웹앱 |

---

## 1. 준비물

- [ ] Cloudflare 계정 (무료): https://dash.cloudflare.com/sign-up
- [ ] Node.js 20 이상: https://nodejs.org (LTS 버전 설치)
- [ ] 코드 받기

```bash
git clone https://github.com/lecoeur-dr/onlineplatform.git
cd onlineplatform
npm install
```

## 2. Cloudflare 로그인 · 데이터베이스 만들기

```bash
npx wrangler login                 # 브라우저가 열리면 '허용'
npx wrangler d1 create gyomusil    # 데이터베이스 생성
```

출력에 나오는 `database_id = "xxxxxxxx-...."` 값을 복사해 `wrangler.toml` 의 아래 줄을 바꿉니다.

```toml
database_id = "REPLACE_WITH_D1_DATABASE_ID"   # ← 복사한 값으로 교체
```

그다음 표(테이블)를 만듭니다.

```bash
npm run db:init:remote
```

## 3. 1차 배포 (주소 확인용)

```bash
npx wrangler deploy
```

마지막 줄에 `https://online-gyomusil.<계정이름>.workers.dev` 형태의 주소가 나옵니다. **이 주소를 메모**합니다. (아직 로그인은 안 됩니다.)

## 4. 구글 로그인 키 만들기 (Google Cloud 콘솔)

1. https://console.cloud.google.com 접속 → 상단 프로젝트 선택 → **새 프로젝트** (이름 예: `온라인교무실`)
2. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**
   - 사용자 유형: **외부(External)**
   - 앱 이름: `서부초 온라인 교무실`, 지원 이메일: 본인 Gmail
   - 범위(Scopes): 추가하지 않아도 됨 (기본 `email`, `profile`, `openid` 만 사용)
   - 게시 상태
     - **테스트** 상태: '테스트 사용자'에 선생님 Gmail을 등록해야 로그인됨 (최대 100명)
     - **프로덕션(앱 게시)**: 등록 없이 누구나 구글 로그인 가능 → 실제 사용 허락은 웹앱 관리자 승인으로 통제
     - 기본 범위만 쓰는 앱은 구글 심사 없이 게시할 수 있는 것으로 알려져 있음 [확인 필요: 게시 버튼을 누를 때 나오는 안내 확인]
3. **API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - 승인된 리디렉션 URI 에 추가:
     - `https://online-gyomusil.<계정이름>.workers.dev/auth/callback` (3단계에서 메모한 주소 + `/auth/callback`)
     - (PC에서 테스트할 때만) `http://127.0.0.1:8787/auth/callback`
4. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사

## 5. 비밀값 등록 · 관리자 지정 · 재배포

```bash
npx wrangler secret put GOOGLE_CLIENT_ID       # 4단계 클라이언트 ID 붙여넣기
npx wrangler secret put GOOGLE_CLIENT_SECRET   # 4단계 보안 비밀번호 붙여넣기

# 비밀번호 암호화 키 만들기 → 출력값을 복사해서 등록
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
npx wrangler secret put DATA_KEY
```

> ⚠️ **DATA_KEY 는 반드시 따로 보관**하세요 (예: 개인 비밀번호 관리 앱). 이 키를 잃어버리면 저장된 비밀번호를 풀 수 없습니다. 이 키는 저장소나 공유 시트에 절대 올리지 마세요.

`wrangler.toml` 에서 관리자 이메일과 학교 이름을 지정합니다.

```toml
[vars]
SCHOOL_NAME = "서부초등학교"
ADMIN_EMAILS = "관리자gmail주소@gmail.com"   # 교무 담당 (쉼표로 여러 명 가능)
```

다시 배포합니다.

```bash
npx wrangler deploy
```

## 6. 관리자 첫 로그인 → 기존 시트 가져오기

1. 웹앱 주소 접속 → **Google 계정으로 로그인** (ADMIN_EMAILS 에 넣은 계정)
2. 구글 시트 「2026년 서부초 온라인 교무실」 → **파일 → 다운로드 → Microsoft Excel (.xlsx)**
3. 웹앱 **⚙️ 관리자 → 엑셀 가져오기** → 파일 선택
4. 시트별로 어디로 옮겨지는지 미리보기 확인 → 학년도 `2026`, 방식 `바꾸기` → **가져오기 실행**
5. **⚙️ 관리자 → 설정**에서 부서·장소·학급 목록을 학교에 맞게 정리
6. 대시보드의 **확인필요 일정**을 열어 담당·장소를 바로잡기

> 엑셀 파일은 브라우저 안에서만 읽고, 확인한 기록만 서버로 보냅니다. 내려받은 .xlsx 파일에는 비밀번호가 들어 있으니 가져온 뒤 삭제하세요.

## 7. 선생님들께 안내

- 웹앱 주소를 메신저로 공유 → 선생님이 개인 Gmail로 로그인 → **승인대기** 상태가 됨
- 관리자가 **⚙️ 관리자 → 사용자**에서 권한을 `교직원`으로 변경하고, **이름**을 입력 (동료장학 참관 명단에 이 이름이 쓰임)
- 또는 선생님 Gmail을 미리 등록해 두면 첫 로그인부터 바로 사용 가능

## 운영 메모

| 항목 | 방법 |
|---|---|
| 백업 | 관리자 → 백업 (한 달에 한 번 JSON 내려받아 드라이브 보관 권장). 전체 DB: `npx wrangler d1 export gyomusil --remote --output backup.sql` |
| 새 학년도 | 관리자 → 설정에서 기본 학년도 변경 → 연도 복사로 시간표·자유 표 복사 |
| 코드 업데이트 | `git pull` → `npm run db:init:remote` (새 표가 있을 때) → `npx wrangler deploy` |
| 변경 기록 | 관리자 → 변경 기록 (누가 언제 추가·수정·삭제·비밀번호 열람했는지) |
| 비용 | Workers·D1 무료 플랜 범위에서 학교 1곳 사용량은 충분할 것으로 예상 [확인 필요: https://developers.cloudflare.com/workers/platform/pricing/ 의 최신 한도] |
| 주소 바꾸기 | Cloudflare 대시보드 → Workers → online-gyomusil → 설정 → 도메인에서 사용자 지정 도메인 연결 가능 (바꾸면 4단계 리디렉션 URI 도 추가) |

## PC에서 먼저 시험해 보기 (선택)

```bash
cp .dev.vars.example .dev.vars   # DATA_KEY 값 채우기, DEV_LOGIN=1
npm run db:init:local
npm run dev                      # http://127.0.0.1:8787
# 구글 없이 시험 로그인: http://127.0.0.1:8787/auth/dev?email=you@gmail.com
```

`DEV_LOGIN` 은 `.dev.vars`(내 PC)에만 있고 실제 배포에는 없으므로, 배포된 웹앱에서는 시험 로그인이 동작하지 않습니다.
