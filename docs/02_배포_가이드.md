# 온라인 교무실 — Cloudflare 배포 가이드

> 처음 한 번만 하면 되는 작업입니다. 소요 시간은 약 30~40분으로 예상합니다.
> **방법 A(추천)** 는 프로그램 설치 없이 웹 화면에서 클릭으로 진행합니다. GitHub 저장소와 연결해 두면 코드가 바뀔 때마다 자동으로 다시 배포됩니다.
> 화면의 메뉴 이름은 Cloudflare·Google 화면 개편에 따라 조금 다를 수 있습니다.

## 방법 A — Cloudflare 웹 화면 + GitHub 자동 배포 (추천)

| 순서 | 할 일 | 어디서 | 결과물 |
|---|---|---|---|
| A1 | Cloudflare 가입 | dash.cloudflare.com | 계정 |
| A2 | 데이터베이스(D1) 만들기 | Cloudflare | **데이터베이스 ID** → Claude에게 전달 |
| A3 | (Claude) 설정 파일에 ID 반영 후 저장소에 올림 | - | - |
| A4 | GitHub 저장소 연결 → 첫 배포 | Cloudflare | **웹앱 주소** |
| A5 | 구글 로그인 키 만들기 | Google Cloud 콘솔 | 클라이언트 ID · 보안 비밀번호 |
| A6 | 비밀값 4개 등록 | Cloudflare | - |
| A7 | 관리자 첫 로그인 → 엑셀 가져오기 | 웹앱 | - |

### A1. Cloudflare 가입
- https://dash.cloudflare.com/sign-up → 이메일 인증까지 완료

### A2. 데이터베이스 만들기
1. 왼쪽 메뉴 **저장소 및 데이터베이스(Storage & Databases) → D1 SQL Database → 데이터베이스 만들기(Create)**
2. 이름: `gyomusil` (꼭 이 이름), 위치: 기본값 또는 아시아·태평양
3. 만들어진 화면의 **Database ID** (`xxxxxxxx-xxxx-…` 형태)를 복사해 Claude에게 알려 주세요
   - 이 ID는 비밀번호가 아니라 주소 같은 값이라 공개 저장소에 들어가도 괜찮습니다

### A3. (Claude가 진행) `wrangler.toml` 에 데이터베이스 ID 반영 → 저장소에 올림

### A4. GitHub 저장소 연결 (자동 배포)
> 첫 배포는 Claude가 터미널로 이미 끝냈습니다 → `https://onlineplatform.lecoeur.workers.dev`
> 여기서는 이미 만들어진 Worker에 GitHub 저장소만 연결합니다.

1. Cloudflare 대시보드 → **Workers 및 Pages(Workers & Pages)** → `onlineplatform` 클릭
2. **설정(Settings) → 빌드(Build) → Git 리포지토리 연결(Connect)**
3. GitHub 계정 연결 (처음이면 GitHub 화면이 열림 → `lecoeur-dr` 선택 → `onlineplatform` 저장소만 허용 → **Install & Authorize**)
4. 설정
   - 리포지토리: `lecoeur-dr/onlineplatform`
   - 브랜치: 최신 코드가 합쳐진 저장소 기본 브랜치 [확인 필요: Claude에게 현재 기준 브랜치 확인]
   - 빌드 명령(Build command): 비워 둠
   - 배포 명령(Deploy command): `npm run deploy:ci` ← 데이터베이스 표 갱신 + 배포를 함께 실행
   - 루트 디렉터리: `/` (기본값)
5. **연결(Connect)** → 이후 해당 브랜치에 코드가 올라오면 1~3분 뒤 자동 배포
   - 배포가 실패하면 **배포(Deployments) → 빌드 로그** 내용을 복사해 Claude에게 전달

### A5. 구글 로그인 키 만들기
아래 **4. 구글 로그인 키 만들기** 항목과 같습니다. 리디렉션 URI는 A4 주소 + `/auth/callback`

### A6. 비밀값 4개 등록
1. Workers 및 Pages → `onlineplatform` → **설정(Settings) → 변수 및 비밀(Variables and Secrets) → 추가**
2. 유형은 모두 **비밀(Secret)** 로 선택

| 이름 | 값 |
|---|---|
| `ADMIN_EMAILS` | 관리자 Gmail 주소 (여러 명이면 쉼표로 구분) |
| `GOOGLE_CLIENT_ID` | A5의 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | A5의 클라이언트 보안 비밀번호 |
| `DATA_KEY` | `웹앱주소/keygen.html` 에 들어가서 나온 값 복사 |

3. 저장(배포) → 웹앱 주소에서 **Google 계정으로 로그인**

> ⚠️ `DATA_KEY` 는 비밀번호 관리 앱 등 **안전한 곳에 따로 보관**하세요. 잃어버리면 저장된 비밀번호를 풀 수 없습니다.

### A7. 관리자 첫 로그인 → 엑셀 가져오기
아래 **6. 관리자 첫 로그인** 항목과 같습니다.

### 이후 업데이트
Claude가 저장소에 코드를 올리면 Cloudflare가 **자동으로 다시 배포**합니다. 따로 할 일은 없습니다.

## 방법 B — 터미널로 배포 (개발 환경이 있을 때)

아래 4·6·7번 항목은 방법 A에서도 함께 참고합니다.

### 전체 흐름

| 순서 | 할 일 | 어디서 |
|---|---|---|
| 1 | 준비물 설치, 코드 받기 | 내 PC |

| 3 | 1차 배포 → 웹앱 주소 확인 | 터미널 |

| 6 | 관리자 첫 로그인 → 엑셀 가져오기 | 웹앱 |
| 7 | 선생님들께 주소 안내 → 승인 | 웹앱 |

## 1. 준비물

- [ ] Cloudflare 계정 (무료): https://dash.cloudflare.com/sign-up
- [ ] Node.js 20 이상: https://nodejs.org (LTS 버전 설치)
- [ ] 코드 받기

```bash
git clone https://github.com/lecoeur-dr/onlineplatform.git
cd onlineplatform
npm install
```

## 2. Cloudflare 로그인 · 데이터베이스 만들기

```bash
npx wrangler login                 # 브라우저가 열리면 '허용'
npx wrangler d1 create gyomusil    # 데이터베이스 생성
```

출력에 나오는 `database_id = "xxxxxxxx-...."` 값을 복사해 `wrangler.toml` 의 아래 줄을 바꿉니다.

```toml
database_id = "REPLACE_WITH_D1_DATABASE_ID"   # ← 복사한 값으로 교체
```

그다음 표(테이블)를 만듭니다.

```bash
npm run db:init:remote
```

## 3. 1차 배포 (주소 확인용)

```bash
npx wrangler deploy
```

마지막 줄에 `https://onlineplatform.lecoeur.workers.dev` 형태의 주소가 나옵니다. **이 주소를 메모**합니다. (아직 로그인은 안 됩니다.)

## 4. 구글 로그인 키 만들기 (Google Cloud 콘솔)

> 구글 화면은 자주 바뀝니다. 최근 화면에서는 'OAuth 동의 화면'이 **Google 인증 플랫폼(Google Auth Platform)** 메뉴 아래 **브랜딩 · 대상 · 클라이언트** 탭으로 나뉘어 있습니다. [확인 필요: 실제 메뉴 이름]

### 4-1. 프로젝트 만들기
1. https://console.cloud.google.com 접속 → 관리자 Gmail로 로그인 (처음이면 약관 동의)
2. 화면 맨 위 **프로젝트 선택** 상자 → **새 프로젝트**
3. 프로젝트 이름: `onlineplatform` (아무 이름이나 가능) → 만들기 → 알림에서 **프로젝트 선택**

### 4-2. 동의 화면(브랜딩) 설정 — 로그인할 때 사용자에게 보이는 앱 정보
1. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면** (또는 검색창에 `Google Auth Platform`)
2. **시작하기(Get started)** 클릭 후 순서대로 입력
   - 앱 이름: `서부초 온라인 교무실`
   - 사용자 지원 이메일: 본인 Gmail
   - 대상(Audience): **외부(External)** ← 개인 Gmail 선생님도 로그인하려면 반드시 외부
   - 연락처 이메일: 본인 Gmail
   - 사용자 데이터 정책 동의 체크 → **만들기**
3. 범위(Scopes / 데이터 액세스): **추가하지 않음** (기본 `openid`, `email`, `profile` 만 사용)

### 4-3. 게시 상태 정하기 (대상 탭)
| 상태 | 누가 로그인 가능 | 추천 |
|---|---|---|
| 테스트 | '테스트 사용자'에 등록한 Gmail만 (최대 100명) | 시험 운영 때 |
| 프로덕션(앱 게시) | 구글 계정이 있는 누구나 로그인 → 실제 사용은 웹앱 관리자 **승인**으로 통제 | 실제 운영 때 |

- 기본 범위만 쓰는 앱은 구글 심사 없이 게시할 수 있는 것으로 알려져 있음 [확인 필요: **앱 게시** 버튼을 누를 때 나오는 안내 확인]

### 4-4. 클라이언트(로그인 키) 만들기
1. **클라이언트(Clients) → + 클라이언트 만들기** (예전 화면: 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID)
2. 애플리케이션 유형: **웹 애플리케이션**, 이름: `onlineplatform-web`
3. **승인된 자바스크립트 원본**: 비워 둠
4. **승인된 리디렉션 URI → + URI 추가**
   - `https://onlineplatform.lecoeur.workers.dev/auth/callback` ← 한 글자라도 다르면 `redirect_uri_mismatch` 오류
   - (PC에서 테스트할 때만) `http://127.0.0.1:8787/auth/callback`
5. **만들기** → 창에 나오는 **클라이언트 ID**(`…apps.googleusercontent.com`)와 **클라이언트 보안 비밀번호**(`GOCSPX-…`) 복사
   - 보안 비밀번호는 이 창에서만 전체가 보일 수 있으니 바로 안전한 곳에 저장 [확인 필요]

### 4-5. 자주 나는 오류
| 오류 | 원인 · 해결 |
|---|---|
| `redirect_uri_mismatch` | 4-4의 리디렉션 URI 오타 확인 (https, 끝의 `/auth/callback`) |
| `access_denied` / 앱 접근 차단 | 테스트 상태인데 테스트 사용자로 등록 안 된 Gmail → 등록하거나 앱 게시 |
| `GOOGLE_CLIENT_ID 가 설정되지 않았습니다` | Cloudflare 비밀값 등록 전 (A6) |

## 5. 비밀값 등록 · 관리자 지정 · 재배포

```bash
npx wrangler secret put GOOGLE_CLIENT_ID       # 4단계 클라이언트 ID 붙여넣기
npx wrangler secret put GOOGLE_CLIENT_SECRET   # 4단계 보안 비밀번호 붙여넣기

# 비밀번호 암호화 키 만들기 → 출력값을 복사해서 등록
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
npx wrangler secret put DATA_KEY
```

> ⚠️ **DATA_KEY 는 반드시 따로 보관**하세요 (예: 개인 비밀번호 관리 앱). 이 키를 잃어버리면 저장된 비밀번호를 풀 수 없습니다. 이 키는 저장소나 공유 시트에 절대 올리지 마세요.

관리자 이메일도 비밀로 등록합니다 (공개 저장소에 이메일이 올라가지 않도록).

```bash
npx wrangler secret put ADMIN_EMAILS           # 교무 담당 Gmail (쉼표로 여러 명 가능)
```

다시 배포합니다.

```bash
npx wrangler deploy
```

## 6. 관리자 첫 로그인 → 기존 시트 가져오기

1. 웹앱 주소 접속 → **Google 계정으로 로그인** (ADMIN_EMAILS 에 등록한 계정)
2. 구글 시트 「2026년 서부초 온라인 교무실」 → **파일 → 다운로드 → Microsoft Excel (.xlsx)**
3. 웹앱 **⚙️ 관리자 → 엑셀 가져오기** → 파일 선택
4. 시트별로 어디로 옮겨지는지 미리보기 확인 → 학년도 `2026`, 방식 `바꾸기` → **가져오기 실행**
5. **⚙️ 관리자 → 설정**에서 부서·장소·학급 목록을 학교에 맞게 정리
6. 대시보드의 **확인필요 일정**을 열어 담당·장소를 바로잡기

> 엑셀 파일은 브라우저 안에서만 읽고, 확인한 기록만 서버로 보냅니다. 내려받은 .xlsx 파일에는 비밀번호가 들어 있으니 가져온 뒤 삭제하세요.

## 7. 선생님들께 안내

- 웹앱 주소를 메신저로 공유 → 선생님이 개인 Gmail로 로그인 → **승인대기** 상태가 됨
- 관리자가 **⚙️ 관리자 → 사용자**에서 권한을 `교직원`으로 변경하고, **이름**을 입력 (동료장학 참관 명단에 이 이름이 쓰임)
- 또는 선생님 Gmail을 미리 등록해 두면 첫 로그인부터 바로 사용 가능

## PC에서 먼저 시험해 보기 (선택)

```bash
cp .dev.vars.example .dev.vars   # DATA_KEY 값 채우기, DEV_LOGIN=1
npm run db:init:local
npm run dev                      # http://127.0.0.1:8787
# 구글 없이 시험 로그인: http://127.0.0.1:8787/auth/dev?email=you@gmail.com
```

`DEV_LOGIN` 은 `.dev.vars`(내 PC)에만 있고 실제 배포에는 없으므로, 배포된 웹앱에서는 시험 로그인이 동작하지 않습니다.

## 사용량과 한도 (무료 플랜)

### Cloudflare 무료 한도

출처: [D1 요금](https://developers.cloudflare.com/d1/platform/pricing/), [Workers 요금](https://developers.cloudflare.com/workers/platform/pricing/) (2026-09-30 검색 기준)

| 항목 | 무료 한도 |
|---|---|
| 서버 요청 (Workers) | 하루 100,000건 |
| 데이터 읽기 (D1) | 하루 5,000,000행 |
| 데이터 쓰기 (D1) | 하루 100,000행 |
| 저장 용량 (D1) | 총 5GB |

한도를 넘기면 그날 한도가 초기화될 때까지 데이터 조회가 오류로 막힙니다. 유료 플랜으로 바꾸면 한도가 늘어납니다 [확인 필요: 유료 요금].

### 우리 학교 예상 사용량 (2026년 시트 기준 추정)

| 항목 | 계산 근거 | 하루 예상 | 한도 대비 |
|---|---|---|---|
| 데이터 읽기 | 달력·대시보드 1회 ≈ 600행, 기타 화면 ≈ 50행 → 1인 하루 달력 10회 + 기타 10회 ≈ 6,500행 × 50명 | 약 33만 행 | 약 7% |
| 서버 요청 | 화면 1번에 요청 약 3건 × 1인 20회 × 50명 | 약 3,000건 | 약 3% |
| 데이터 쓰기 | 수정 1건 = 기록 1 + 변경기록 1행. 엑셀 전체 가져오기 1회 ≈ 2,000행 | 수백 ~ 수천 행 | 5% 미만 |
| 저장 용량 | 현재 기록 약 900건 | 수 MB 이하 | 0.1% 미만 |

- **결론**: 교직원 50명이 매일 써도 무료 한도의 10% 안팎으로 예상됩니다. 수치는 추정이며, 실제 사용량은 Cloudflare 대시보드 → D1 → gyomusil → 지표(Metrics)에서 확인할 수 있습니다.
- 학사일정은 **보고 있는 학년도(14개월)만** 읽기 때문에, 해가 지나 기록이 쌓여도 화면 1번에 읽는 양은 크게 늘지 않습니다.
- 한도가 부담되는 경우는 **여러 학교가 한 데이터베이스를 함께 쓰는 경우**입니다. 이때는 학교마다 따로 배포하는 것을 권장합니다 (배포 가이드를 학교별로 한 번씩 진행).
